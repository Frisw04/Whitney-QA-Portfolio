## AI-Assisted QA Workflow

I use AI as a technical investigation and development aid while maintaining human verification of software behavior.

My workflow includes:

1. Define the expected application behavior.
2. Reproduce the observed defect.
3. Collect logs and behavioral evidence.
4. Use AI-assisted code investigation to identify possible failure paths.
5. Evaluate suggested code changes.
6. Build and test changes on physical devices.
7. Reject fixes that do not resolve the original defect.
8. Perform regression testing after successful changes.

I do not assume that AI-generated code or explanations are correct. Changes are validated through builds, observed behavior, logs, and repeated testing.

## QA Case Studies

### 1. PencilKit Drawing Persistence

Investigated cases where drawings could disappear or fail to restore correctly during device rotation, page changes, or application state updates.

The investigation included reproduction testing, canvas-state analysis, persistence testing, and regression verification.

### 2. Keyboard Viewport & Layout Behavior

Investigated differences in page and text-editor behavior when the software keyboard appeared in portrait and landscape orientations.

Testing included viewport measurements, available writing-space evaluation, device rotation, and physical-device verification.

### 3. Multi-Page Data Persistence & Migration

Tested the transition of Living Pages from a single-page-per-day architecture to a multi-page system.

Testing included page identity, SwiftData persistence, legacy data compatibility, schema migration, page switching, relaunch behavior, and regression testing.
