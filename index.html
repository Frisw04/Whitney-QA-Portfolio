QA Case Studies

Case Study 1: PencilKit Drawing Persistence Bug

Problem: User drawings could disappear or fail to restore correctly after events such as device rotation, page changes, or application state updates.

Investigation: I reproduced the issue across devices and tested different application states to determine whether the failure involved the user interface, canvas state, or persistence layer.

Testing Approach: I analyzed application behavior, reviewed state changes, compared expected versus actual results, and verified changes through repeated regression testing.

Result: Improved understanding of PencilKit lifecycle behavior, drawing state management, and persistence timing.

Case Study 2: Keyboard Viewport & Layout Behavior

Problem: The application writing area behaved differently when the software keyboard appeared. The final lines of content could become hidden, and page layout changed between portrait and landscape orientations.

Investigation: I reproduced the issue on physical iPhone and iPad devices while testing different screen orientations, keyboard states, and page configurations. I analyzed whether the issue was caused by text layout, viewport sizing, or application geometry calculations.

Testing Approach: I compared expected and actual behavior during keyboard presentation, rotation, and page rendering. I used debugging information to evaluate viewport size, available writing space, and content positioning.

Result: Improved the writing experience by ensuring the usable page area remained visible when the keyboard appeared while maintaining consistent page behavior across devices.

Case Study 3: Multi-Page Data Persistence & Migration

Problem: Living Pages originally stored one journal page per day. When multi-page support was introduced, the data architecture needed to support multiple independent pages while preserving the correct text, drawings, attachments, and page settings.

Investigation: I tested page creation, page switching, device rotation, application relaunch, and persistence across multiple pages. During testing, I identified cases where page-specific state could restore from the wrong page or where drawing state could temporarily disappear during rotation.

Testing Approach: I used page-specific identifiers, application logs, repeated reproduction steps, and regression testing to trace data through the SwiftData persistence layer. I compared Page 1 and Page 2 behavior and tested whether each page maintained independent text, drawing, attachment, and configuration state.

Migration Testing: I tested the transition from the original single-page data model to the new multi-page architecture. This included verifying schema migration behavior, legacy Page 1 compatibility, page creation, and preservation of existing data.

Result: The investigation helped establish a page-scoped persistence architecture in which individual pages could be identified and tested independently. It also exposed rotation and autosave edge cases for continued regression testing.
